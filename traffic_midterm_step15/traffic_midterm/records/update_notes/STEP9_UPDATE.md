# 第九步核心更新 - 2026-10-19

這次更新保留data、既有results、reports與第八步原始JSON，不改寫先前模型答案，也不把開發範例變成正式測試成績。

## 新增功能

1. 主張欄留空且選本機模式時，先由本機Qwen2.5擷取案件欄位及主張，再進行分析。也可按「預覽模型擷取」單獨檢查；人工採用後，分析使用固定主張，結果會明確標為supplied_claims。
2. 每個原文主張必須附上事故描述內逐字相同的引用。欄位值也須能在引用中找到。引用只表示使用者敘述的來源，不表示內容已被驗證。
3. 若責任主張有明確的行為前提，另外新增因果待查問題。例如「A無照 -> A全責」之間加入「A無照是否與事故有因果關係？」。此項標為generated_check_question，source_quote留空；不是把原文沒有的因果指控造出來。沒有前提連結時不猜測建立因果鏈。
4. 明確區分speaker（誰提出主張）與subject（主張指向誰）。不明當事人維持unknown。影片名稱仍不是已讀取影片的證據，擷取步驟不會自動填入evidence assertions。
5. 所有模型條件共用較清楚的主張類型與證據定義。驗證組逐項判斷，保留raw_model_result、規則門檻、前後標籤。LLM Only和RAG不套用驗證門檻，避免把基準組改成規則答案。
6. 事實主張被模型標為過度推論時，增加提醒；不私下替模型改標籤。調解員不再把任何Overgeneralized都寫成全部責任推論，也不將模型的Supported直接當成已證實事實。
7. 網頁修改輸入後不再保留可誤認為新輸入結果的舊答案。生成中暫停編輯；出錯時清除舊輸出並顯示本次錯誤。失敗原始回應仍保存於results/model_errors。

## 怎麼使用

更新後重新啟動 `python main.py serve`，瀏覽器Ctrl+F5。主張JSON預設留空。

- 本機完整流程：主張留空，選本機LLM、RAG或RAG+Verification，再按分析。
- 擷取預覽：按預覽模型擷取，核對案件與原文引用，可匯出traffic-extraction.json。按採用主張會填入固定JSON；請核對後分析。
- 正式三組比較：必須對三組提供相同、已確認的主張，不能每組各擷取一次再把差異全歸因於Verification。既有evaluate工具仍使用固定主張，不執行或評分端到端擷取。
- 自動新增的因果問題與原文主張應分開評估；擷取precision/recall不可把系統新增的問題算作原文成功擷取。

## 可選命令列

輸入是含description欄位的JSON。擷取命令：

```
python main.py extract --input data/demo.json --output results/extraction_demo.json
```

此動作使用免費本機模型，無付費API。模擬API自動測試無法證明真實模型會正確擷取，仍需第十步本機試跑與人工核對。

## 限制與實驗紀律

原文引用存在不代表語意解讀正確。模型仍可能認錯當事人、否定詞、語境或前提；程式會攔截部分明顯不符，但不能保證語意全對。複雜否定、超出predicate詞彙的行為與長事故描述尤其需要人工檢查。輸出上限可能造成長文擷取失敗，失敗不可當有效樣本。

第八步的範例已反覆用於開發與修正，不能再稱為獨立盲測。正式測試案例與人工標註應另行準備、固定後不再用來調整提示。prompt_version=step9-20261019；更換提示後的輸出不可與舊版混在同一設定中計算成績。
